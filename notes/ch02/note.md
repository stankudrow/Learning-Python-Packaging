### Факториал

Факториал целого числа - это произведение всех натуральных ("естественных") чисел от 1 до этого числа. Например, факториал 5, или `5!`, равен `5 * 4 * 3 * 2 * 1 = 120`. Факториал можно обощённо записать:

- итеративно -> `n! = n * (n - 1) * (n - 2) * ... * 1`;
- [рекуррентно](https://ru.wikipedia.org/wiki/%D0%A0%D0%B5%D0%BA%D1%83%D1%80%D1%80%D0%B5%D0%BD%D1%82%D0%BD%D0%B0%D1%8F_%D1%84%D0%BE%D1%80%D0%BC%D1%83%D0%BB%D0%B0) -> `n! = n * (n - 1)!`;

Исходя из определения, `1! = 1`, ибо начинается с единицы и на ней же заканчивается и без промежуточных сомножителей. А как быть с `0!`? По определению, `1! = 1 * 0!`, но `1! = 1`, а значит `0!` можно принять за единицу.

Реализация факториала - классическая задача на овладение [рекурсией](https://ru.wikipedia.org/wiki/%D0%A0%D0%B5%D0%BA%D1%83%D1%80%D1%81%D0%B8%D1%8F), анализ вычислительной сложности, улучшения и замеры производительности.

Рассмотрим наивную реализацию:

```python
def factorial_recursive_naive(n: int) -> int:
    if n < 0:
        raise ValueError("n must be non-negative integer")
    if n < 2:  # n in (0, 1)
        return 1
    return n * factorial(n - 1)
```

Хорошо, что предусмотрели защиту от подачи отрицательного числа и заодно спасли функцию от переполнения стека. Но всё же есть недостаток: это условие проверяется при каждом вызове, а это всё же дорого и отъём вычислительной мощи. [Асимптотическая сложность](https://ru.wikipedia.org/wiki/%D0%92%D1%8B%D1%87%D0%B8%D1%81%D0%BB%D0%B8%D1%82%D0%B5%D0%BB%D1%8C%D0%BD%D0%B0%D1%8F_%D1%81%D0%BB%D0%BE%D0%B6%D0%BD%D0%BE%D1%81%D1%82%D1%8C) этой функции `O(n)` - просто разложите вызовы и увидите последовательную лестницу.

А можно и нужно сделать итеративную версию:

```python
def factorial_iterative(n: int) -> int:
    if n < 0:
        raise ValueError("n must be non-negative integer")
    if n < 2:
        return 1
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result
```

Здесь условие проверки на отрицательность уместно и будет выполнено один раз, а ещё обходимся одним вызовом функции и не нагружаем стек. Сложность всё та же: `O(n)` (один цикл).

Здесь хватит простецких и простых решений, остальное в исходниках.

### Числа Фибоначчи

Названы в честь итальянского математика [Леонардо Пизанского](https://ru.wikipedia.org/wiki/%D0%A4%D0%B8%D0%B1%D0%BE%D0%BD%D0%B0%D1%87%D1%87%D0%B8), который предложил задачу о размножающихся кроликах в своей книге [Liber Abaci (1202)](https://ru.wikipedia.org/wiki/%D0%9A%D0%BD%D0%B8%D0%B3%D0%B0_%D0%B0%D0%B1%D0%B0%D0%BA%D0%B0). Условия задачи:

- есть молодая чета (пара) кроликов на начало первого месяца;
- каждая чета кроликов породит новую чету за месяц;
- кролики не умирают.

А теперь посмсотрим движение по месяцам:

1. 1 - одна пара кроликов и она растёт, молодеет и созревает к размножению.
2. 1 - та же чета (пара), но уже созревшая к началу месяца и приступившая к "соитию", т.е. к началу следующего месяца можно ожидать новую чету кроликов.
3. 2 - родительская пара и детская - родительская пара начинает сношаться, а новорождённые пока растут (им хватит месяца).
4. 3 - рождена чета (ей месяц на взросление), родители из месяца 1 (и 2) снова размножаются, а дети из месяца 3 также зачинают потомство.
5. 5 - две пары породили 2 пары и созрела чета из прошлого месяца, поэтому 2 пары растут, а 3 размножаются
6. 8 - 3 пары дали 3, а ещё 2 четы подросли, итого 3 + 3 + 2 = 3 + 5 = 8, из них 5 зачатят, а 3 растут.
7. 13 - 5 дают 5, а 3 подросли, т.е. 5 + 5 + 3 = 5 + 8 = 13, и теперь 8 множатся, а 5 растут
8. и так далее по уже, надеюсь, понятной схеме.

Видно, что [ряд Фибоначчи](https://ru.wikipedia.org/wiki/%D0%A7%D0%B8%D1%81%D0%BB%D0%B0_%D0%A4%D0%B8%D0%B1%D0%BE%D0%BD%D0%B0%D1%87%D1%87%D0%B8]) выстраивается таким: `1, 1, 2, 3, 5, 8, 13, 21, 34, ...` и получается он по незамысловатой схеме: `F_0 = 1; F_1 = 1; F_n = F_{n-1} + F_{n-2} for n > 1`. Ну или могут начинать ряд с 0.

Рекурсивное решение алгоритма отыскания n-го числа Фибоначчи:

```python
def fibonacci(n):
    if n < 0:
        raise ValueError("n must be a non-negative integer")
    if n < 2:
        return n
    return fibonacci(n-1) + fibonacci(n-2)
```

Итеративное решение:

```python
def fibonacci(n):
    if n < 0:
        raise ValueError("n must be a non-negative integer")
    if n < 2:
        return n
    a, b = 0, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b
```

### Динамическое программирование

Динамическое программирование (ДП) (dynamic programming, DP) — это способ решать сложные задачи, разбивая их на перекрывающиеся подзадачи и сохраняя промежуточные выдатки (результаты), чтобы не пересчитывать их многократно ибо они могут встретиться во время исполнения алгоритма.

Два основополагающих признака, где можно рассмотреть ДП:

- Оптимальная подструктура: оптимальное (лучшее) решение задачи строится из оптимальных (лучших) решений подзадач. А теперь чуть доходчивее: если умеешь решать лучшим (оптимальным) способом основные (базовые) случаи/подзадачи, а на их основе приходить к большим задачам, которые в свою очередь будут подзадачами для дальнейших задач и каждые такие переходы достигаются лучшим способом, вот это и есть оптимальная подструктура.
- Перекрывающиеся (под)задачи: когда при решении (большей) задачи возникает необходимость решать одни и те же более мелкие подзадачи. И вот чтобы не решать уже решённое, подзадачи сохраняются (кэшируются) и вместо их перерешивания, возвращается их выдаток (результат).

Подходы ДП:

- Сверху-вниз (top-down), или мемоизация — рекурсивный подход с кэшированием: вызовы сохраняются вместо повторного вычисления. Использовать разумно, потому что кэш может распухнуть.
- Снизу-вверх (bottom-up), или табуляция — итеративный подход, когда заранее определяется порядок решения с заполнением таблицы (вдруг потребуются раннее решённые значения) или сохранением состояния (как две переменные в Фибоначчи). Это больше про динамику решения, программируемого по ходу исполнения алгоритма, а не про тупое заполнение массива (да и не обязательно массива).
